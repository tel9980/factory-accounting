# 小工厂记账财务小程序

面向**以收取加工费为主要收入**的小型工厂：记录应收（客户欠我）、应付（我欠供应商）、日常支出、批量导入、对账、报表与备份。**零服务器成本**，小白也能自己部署使用。

## 技术架构

| 层 | 技术 | 说明 |
|---|---|---|
| 前端 | 微信小程序（原生） | 一个主页面 + 7 个功能页签，无需后端服务器 |
| 后端 | Cloudflare Workers（Hono） | 所有 API 跑在边缘节点，免费额度够用 |
| 数据库 | Cloudflare D1（SQLite），支持多账套（DB / DB2 / DB3） | 结构化存单、流水、口令、快照 |
| 托管 | GitHub | 代码托管，改完 `wrangler deploy` 即上线 |

## 功能清单

- **首页看板**：本月收 / 本月付 / 本月结余、客户欠我、我欠别人、经营毛利、手头现金合计
- **一句话记账**：输入「收张老板5000」「工资5000」「付王五金货款3000」自动识别入账
- **应收**：记订单（客户、产品、金额、约定收款日、经手人）、收款、交付、改、删、搜索、对账、月结
- **应付**：记应付单（供应商、金额、备注、经手人）、付款、改、删、对账、月结
- **支出**：六分类（工资/水电/房租/采购/辅料/其他）+ 现付支出 + 经手人
- **固定支出**：工资、房租等每月到号自动记一笔，可「立即补记本月」
- **批量导入**：从 Excel 复制多行粘贴导入，支持 应收 / 应付 / 支出 / 期初应收 / 期初应付，末尾可带日期
- **报表**：年度流水报表（按月/分类/应收应付汇总）、月度收付柱状图、导出 Excel（CSV）、复制报表
- **历史**：已结清的应收 / 应付
- **单位**：客户 / 供应商汇总，往来明细一键复制
- **资金账户**：现金 / 银行卡 / 微信 / 支付宝多口袋，各账户自动算余额，可加期初余额、改名、加新账户
- **预收款 / 预付款**：客户先给钱、供应商先收定金，先挂账，开单后可一键抵扣（只冲往来，不动现金）
- **防重复录入**：同一天同分类同金额的支出、7 天内同供应商同金额的应付，录入时弹窗确认一次，防手抖记两遍
- **自定义分类**：支出 / 收入分类可自己加删，报表与预算按分类统计
- **员工借支 / 报销**：借出钱给员工（不冲成本，只减现金）→ 报销时选分类冲借支（不动现金）→ 没花完可退回余款，未清借支合计一眼看到
- **坏账核销**：应收要不回来 / 供应商免了钱，可以「核销」一部分或全部，只抹往来不动现金；核销记录可查可撤销，净资产与应收统计自动扣掉核销部分
- **账户内部转账**：现金存银行、微信提现，两边账户余额同步变动，但不算收入也不算支出，不影响利润
- **提醒汇总**：首页把该管的事一次列清（逾期应收、7 天到期收付、预算超支、未认领流水、未清借支、未开发票）
- **发票台账**：开出发票 / 收到发票分开记（号码、对象、金额、税额、日期），本月开出收到和税额自动汇总，已收款未开票自动提示；只做台账不进收支，不重复算钱
- **固定资产折旧**：录设备原值/买入日期/年限/残值率，按直线法自动算月折旧、累计折旧、净值，可一键把本月折旧记成一笔支出（防重复）
- **银行流水对账**：粘贴银行卡/微信账单（日期,收/付,金额,摘要），一笔笔「抵应收 / 抵应付 / 记成一笔账」，带方向校验，不会把付款错抵成收款
- **导入模板导出**：每一类导入都能一键导出一份 CSV 模板，发到电脑用 Excel 填好、存 CSV UTF-8 再发回来导入
- **提醒**：逾期 30 天红条、7 天内到期黄条
- **操作日志**：记录每笔增删改、收付款、锁定等动作，报表页可查最近 100 条
- **备份**：一键全量备份（复制文本）、每日自动云端快照（保留 30 份）、自动同步到 Markdown 笔记站、一键恢复（粘贴备份文本，恢复前自动留快照）
- **访问口令**：首次使用自设口令，所有数据接口需口令访问，可改口令

## 快速开始

1. **后端**：`cd backend && npm install`，把 `wrangler.toml` 里的 `database_id` 换成你的 D1 库，执行 `schema.sql` 建表，再 `npx wrangler deploy`。
2. **前端**：微信开发者工具导入 `frontend` 目录，把 `frontend/pages/index/index.js` 顶部 `API_BASE` 改成你的 Worker 地址。
3. **上线**：微信公众平台把该域名加进 `request` 合法域名；本地调试勾选「不校验合法域名」。

详见 [`DEPLOYMENT.md`](./DEPLOYMENT.md)。

### 备份到笔记站（可选）

账本可自动同步为 Markdown 笔记，存到外部笔记站（本项目默认接一个 Workers + D1 的 Markdown 笔记服务，如 `https://md.1211.cc.cd`）：

```bash
npx wrangler secret put NOTES_PASS     # 笔记站的编辑口令
```

`wrangler.toml` 的 `[vars]` 里填 `NOTES_BASE`（笔记站地址）和 `NOTES_SLUG`（笔记 slug）。部署后，小程序「报表」页点「备份到笔记站」手动同步，Worker 每日 cron 也会自动同步一次。

## 数据模型

- `orders`：应收单（客户、产品、金额、状态、已收、约定收款日、经手人）
- `accounts`：资金账户（名称、类型、期初余额）
- `categories`：收支分类（支出类 / 收入类，可增删）
- `advances`：预收 / 预付（方向、对象、金额、已抵扣）
- `loans`：员工借支（员工、借出、已报销、已退回）
- `invoices`：发票台账（开出发票 / 收到发票）
- `assets`：固定资产（原值、买入日期、年限、残值率）
- `bank_flows`：银行流水（日期、收付、金额、摘要、是否已认领）
- `writeoffs`：坏账核销记录（应收核销 / 应付豁免、金额、原因）
- `transfers`：账户内部转账（转出账户、转入账户、金额）
- `payables`：应付单（供应商、金额、已付、分类、备注、经手人）
- `ledger`：收付流水（收/付方向，关联订单或应付，或现付支出；`account_id` 记哪个账户，`cash=0` 表示预收预付抵扣不动现金）
- `settings`：系统设置（访问口令）
- `backups`：每日云端快照（全量 JSON，保留 30 份）
- `fixed_expenses`：固定支出（金额、分类、每月几号记、备注）
- `month_lock`：月度结账锁定（锁定月份不可增删改）
- `audit_log`：操作日志（动作、对象、详情、时间）
- `budgets`：支出预算（分类、月度额度）
- `phrases`：常用短语（一句话记账常用语模板）
- `trash`：回收站（删除的单据与流水，保留 30 天）
- `process_log`：生产工序记录
- `process_log`：订单工序流水（订单、工序、经手人、时间）

   - 顺手修了两个真 bug：①`/recon-save` 存台账时一律写 `done=0`，导致「两家金额一致」的核对也被算成未处理，结账前的差异阻断永远存在 → 一致时写 `done=1` 并注明「已核对，两家金额一致」；②`closePrecheck` 统计未处理差异时只看 `done=0`、不看 `state`，把一致项也算进去 → 改成 `done=0 AND state<>'match'`。修完实测：一致的对账不再阻断结账，真差异（900 vs 500）仍能拦住并显示「还有差异没处理」。
165. ✅ **静默失败治理（数字悄悄变 0 的问题）**：以前并发查询里到处是 `.catch(() => null)`，一旦某条 SQL 出错（比如列名写错），界面不报错、只是那个数字变成 0——本轮做了四件事：① 新增 `noteFail(e, tag)` + 请求级 `failBucket`，把失败的查询记成「首页明细: no such table …」这样的短句；② `/dashboard`、`/reminders`、`/health-check` 响应新增 `degraded` 字段，数据体检在多条统计失败时直接多一项「有统计查询失败了」并列出原因；③ **首页容错**——`Promise.all` 里任一查询失败会让整页 500（只在外层兜住结果没用），现在 12 条明细查询各自 catch，首页照常显示、坏掉的那块显示为 0 并在 `degraded` 里说明；④ 真正的 500 也记原因：`app.onError` + 中间件 catch 都写 `error_log`（此前 `msg` 恒为空），并给前端一句人话「服务器出了点问题，已经记下来了（设置 → 数据体检 → 🐞 运行日志）」，不再是空白「加载失败」。实测：把 budgets 表改名 → 首页仍 200、`degraded: ['首页明细: D1_ERROR: no such table: budgets: SQLITE_ERROR']`，恢复后为空；另有静态审计脚本把 705 条 SQL 与 39 张表结构对照，0 处列名/表名问题。

166. ✅ **连点和手滑保护（一张单记成两笔的问题）**：① 后端 `POST /orders` 新增「同客户 + 同金额 2 分钟内又记一张」的拦截，返回 409 `{dup:true, code:'dup_soon'}` 和一句「刚记过一张一样的：甲客户 ¥3000。是又记了一笔吗？」，确认确实又干了一单再点「再记一笔」才写入（带 `confirm_dup:true`）；② 前端 `req()` 新增 `once` 连点锁——录应收、录应付、录支出、收款、付款、批量收款、批量付款七个动作在请求没回来之前，重复点击直接忽略（8 秒兜底解锁，避免网络卡住后按钮永久失效）；③ 配合原有的「记完自查」，重复点击不会再多记一笔，同一天确实有两笔一样的活也只是一句提示、不挡人。

167. ✅ **断网也不丢单（厂里信号差的地方能用）**：以前网络一断，点「记上」只会转圈或者干脆没反应，用户不知道记没记上，重录一遍就可能多一笔。现在：① 录应收/应付/支出、收款、付款这 5 个动作断网时，**先把这笔存在手机上**（`wx.setStorageSync('pending_ops')`），弹一句「这笔记到手机上了，联网后会自动补上（不用重新录）」并清空表单；② 每次进页面（`onShow`）自动补发，也可以点顶部黄条「📤 有 N 笔没发出去」手动重发，补完提示「补上了 N 笔」并刷新数据；③ 后端新增 `op_dedupe(client_id UNIQUE)` 表与 `opSeen/opMark`，五个写接口都接受 `client_id`，**同一个 client_id 只入账一次**——补发、重试、连点都不会记两遍；不带 `client_id` 的老调用完全不受影响。实测：同一 client_id 连发两次 → 只 1 张单、第二次返回 `dup_ok`；收款重复提交 → 已收仍是 500（不是 1000）；付款重复 → 已付 800（不是 1600）；支出重复 → 只 1 条；无 client_id 的老调用照常入账。

168. ✅ **回到某一天的账本（一句话恢复，不再手抄 JSON）**：以前恢复要自己从报表页复制一大段 JSON、粘到设置页的框里，小白根本不敢动。现在设置页多一块「⏮ 回到某一天的账本」——`GET /backup-timeline` 列出最近 12 份备份，每份显示「日期 时间 · 应收 N 单 · 应付 N 单 · 流水 N 条」以及和现在差多少；点「回到这天」先弹窗把**备份里有什么、现在有什么**并排列清楚（「备份里：应收 1 单（¥2000）… 现在：应收 3 单（¥2700）…」），确认后 `POST /backup-restore {id, confirm:true}` 由服务端直接恢复（不带 `confirm` 返回 409 让你再确认一次），恢复前自动存一份快照，选错了还能再回来。**同时修了一个真 bug**：`restoreCore` 原来只写回 `id/customer/item_name/price/status/paid/due_date/operator/created_at`，把 **成本 cost、已核销 written_off、工序 progress、rev、流水的账户 account_id 和 cash 标记全丢了**——恢复后毛利分析变 0、账户余额错乱；现在这些字段一并写回（实测恢复后 cost=700、paid=500 都还在，账户余额 500 与流水一致）。










171. ✅ **家底存档（曲线不会被后来的改单带偏）**：`GET /networth` 是「按现在库里的数据倒推每个月末的家底」，一改老单据，历史那一段曲线就跟着变——月底盘过的家底明明是多少，过两个月看却变了样。现在每个月末自动把家底存一份（`net_snapshots` 表：现金 / 应收 / 应付 / 借款 / 净资产），也可以在家底页点「📌 记下这个月的家底」手动留底；存档列表显示「净资产、比上月多了多少」，**并且和「现在重新算的」对照**：两者不一致就标一句「⚠ 现在重新算是 X（差 Y，说明这月的单据后来改过）」，一眼看出哪个月的账被动过。接口：`GET /networth-snapshots`（存档 + 现值 + 差异）、`POST /networth-snapshot {month,note}`（存/覆盖，没账的月份不给存）、`DELETE /networth-snapshot/:month`。cron 在每月最后一天自动存（跟「目标达成」「催款小结」同一条）。实测：11 月存 6000 → 改单后现值 8000 并标出差 2000 → 重存归零；10 月存 5000、11 月存 9000 → 「比上月 +4000」正确；删除存档后列表回到空。

## 说明

- **「赚了多少」只有一个算法（权责口径）**：净利 = 本月接单额 − 单子上的材料·外协成本 − 现金费用（支出 + 固定支出）− 摊销 − 折旧 − 预提利息。赊购只算欠款、不重复算成本。想看「按收付现金算赚多少」，用报表页「两口径」（现金口径 = 实收 − 实付）。
- 本项目为**个人记账工具**，不含发票、报税、银行对账等企业财务功能；需要正式财务软件请另选。
- 微信**个人主体**小程序无法开通微信支付，若后续要收款到小程序，需升级企业主体（约 300 元/年认证）。
169. ✅ **结账这一步不再吓人：跳过什么、以后能不能补，写清楚**：以前点「结转归档」只看到一串自检项，虽然能「照样结账」，但不知道自己跳过的是什么。现在 `closePrecheck`（backend/index.js:825）每项多三样东西——`after`（跳过的后果一句话）、`fixable`（以后能不能补）、`fix_how`（具体怎么补），`text` 也把后果拼进括号里。六项说明按小白说法：
   - 对账差异没处理：结账后这个月就不能再补记差异了，要补得先去「月结归档」删归档（= 解锁）；
   - 没对过账：不影响账目，只是没核过数；对账随时能做，结账不拦；
   - 没出本月小结：小结是给自己看的月报，不出也能结，结完再出也不影响；
   - 没备份：结账本身不危险，但以后数据出问题就回不到现在这个样子；
   - 有没结清的单：欠款不受影响、到点照样提醒，只是这个月单据金额不能再改；
   - 上个月没结：跳着结不报错，只是按月查报表会缺那一块，回头补结即可。
   `/month-close` 成功时额外返回 `lock_note`（锁住了什么）、`unlock_how`（报表 → 月结归档 → 解锁，改完重新结一次）、`not_affected`（欠款/催款/对账单/报表查看不受影响），前端结账成功弹窗直接照念。
   另外**空月份不再被拦**：`closePrecheck` 先数本月单据和流水，全为 0 时直接 `can_close: true, empty: true` + 「这个月还没有任何单据和流水，不用结账」（原来会因「没出小结」把空月份卡死，新用户第一次点结账就被挡）。归档区删除按钮改名「🔓 解锁（删归档）」，月底收尾面板在该月已锁定时多一行提示。

175. ✅ **钱的三条线（首页一屏看清「还挂着什么」）**：预收款、付给供应商的预付款、员工借支、借款这四样，以前分散在三个页面，谁也说不清「现在到底还挂着多少钱」。新增 `GET /funding` 一次算清：①客户先给的（预收款余额 = 金额 − 已抵扣）②付给供应商的预付款（料还没到）③员工借支没清（按人计数）④外面借的钱（本金余额 + 每月利息）。每行一句人话提示（「还没干活就已经收的钱，不是赚到的」「钱付了、料还没到，记着催货」），首页多一张「💼 钱的三条线」卡，哪一行有数点一下直接去处理页。全为零时明确说「这三块都是干净的」，不再让人瞎猜。实测：预收 2000 + 借支 500 + 借款 10000（6%）→ 显示 2000 / 500 / 10000、每月利息 50 元；还本 4000 后自动变 6000、月息 30，与首页「手头现金」「净资产」完全对得上（净资产前后都是 1500，因为还本同时减少现金和负债）。「🔎 找功能」也加了「预收款 / 借支 / 借款 / 三条线」四个词条。

176. ✅ **合并重名 / 单位改名（同一家记成两个名字，对账永远对不上）**：`GET /party-dups` 把客户/供应商名字按「去掉括号、去掉有限公司/公司/厂/店、去空格」归一后分组，同一组里有两种以上写法就报出来（「兴旺五金」和「兴旺五金（宁波）」），并建议保留用得最多的那个名字；`POST /party-merge {from,to}` 一键改名或合并，把 `orders.customer`、`payables.supplier`、`advances.party`、`recon_log`、`dunning_log`、`statement_log` 一起改，`party_terms`/`party_profiles`/`credit_limits` 这三张 `UNIQUE(party)` 的表**目标已有就删源留目标**（不覆盖你后来填的账期/电话）。前端「单位」页「🔀 合并重名 / 改名」：查重名 → 每个建议直接点「并到 X」，也可以手工填「原名 → 新名」。员工口令不能用（一次改动一大片，只给老板）。改锁定月份的单据名字会被 403 拦住（换月或先解锁）。实测：「兴旺五金」2 单 + 「兴旺五金加工厂」1 单 + 「兴旺五金（宁波）」1 单 → 报出重名并建议保留「兴旺五金」；合并后 3 单归到一家、账期设置保留目标那份（30 天）、`ar_left` 从 5000 变 6000 正确；锁定 11 月后合并被拦，解锁后成功；员工口令 403。**踩到的坑**：SQL 别名用了 `left`（SQLite 关键字）导致查询静默失败、重名永远查不到，改成 `rem` 才出来。
