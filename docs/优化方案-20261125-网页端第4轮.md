# 网页端第 4 轮优化方案（2026-11-25）

> 尺度：稳定 / 高效 / 便捷。范围：`backend/index.js` 里所有内联网页（`/`、`/pc`、`/desk`、`/guide`、`/track`、`/statement-ack`、各类 `-print`），不含小程序前端。
> 基线：HEAD `546bb07`，后端 24,612 行，439 个路由。
> 前 3 轮已做完的不再重复（手机断点、打印隐藏名单、客户对账页、电脑看账台、安全头 / CSP、缓存头三分类、压缩、部分索引、`plOf` / 账期 / 快照缓存）。

---

## 一页摘要

**这轮的三句话：**

1. **稳定**——网页上还有 13 处「看起来成了、其实没成」，其中 4 处会**直接把账记错或把账说成 0**：`/desk` 自动刷新会把你选好的单换掉（钱记到别家）、客户签字的对账单在查询失败时印成「本期结清」、批量对账失败时告诉老板「账是清的」、网页「记支出」把分类的**数字 id** 写进账里（我上一轮引入的）。
2. **高效**——`/desk` 打开一次读 **5–7 万行** D1，而且**每 60 秒自己再跑一遍**：标签页开着 70 分钟就能把免费额度（500 万行/天）打满。`/pc` 为了 6 个数字拉了 19 条查询（约 2.5 万行）。真正需要的数字，一次点击里被重复算了 4 遍。
3. **便捷**——网页端现在只能「看 + 记收款 + 记支出」。**搜单、查客户、付供应商、撤错账、月结、打这一张加工单、认领银行流水、处理员工申请**，后端接口全都写好了，网页一个都没接。

**优先级建议**：第 1 批（A 组）全是「账会错 / 人会信错」，今晚就该修；第 2 批（B 组）把读数降一个数量级；第 3、4 批（C 组）让电脑端真能干活。

## A 组：稳定（13 条）

### A1 ⚠️ 最高危：`/desk` 每 60 秒自动刷新，会把「哪张单」下拉打回第一条，钱记到别的客户头上

- **位置**：`backend/index.js:8833`（`fillForms` 重建下拉）、`:8932`（每次 `load()` 都调）、`:9099`（60 秒定时）
- **现象**：老板娘选好「#128 张老板 还欠 ¥3,000」，在金额框填了 3000，正在翻手机核账号——60 秒到了，或者切回标签页、或刚记完上一笔触发 `load()`——下拉被打回列表第一条（欠得最多那家），金额框里的 3000 **还在**。点「记上」，3000 记到别人头上。成功提示只说「记上了，这张单还欠 ¥X」，**不回单号**，看不出记错了。
- **为什么会这样**：账户下拉有 `localStorage.fa_acc` 记住（`:8839`），单据下拉没有对应处理——第 20 轮加自动刷新时没考虑它会重建表单。
- **改法**：`fillForms` 重建 `rcDoc` 之前先存 `var keep = el('rcDoc').value`，重建后若该 option 仍存在就 `el('rcDoc').value = keep`；同时成功提示改成「记上了 → **#128 张老板**，这张单还欠 ¥X」。更稳一点：表单里已填了金额时，自动刷新直接跳过（`if (el('rcAmt').value || el('exAmt').value) return`）。
- **代价**：小，约 10 行。
- **验证**：`test-web-pages.mjs` 加一段——取页面脚本，断言存在「重建前保存 keep」的语句；再用真请求：选第二张单 → 触发一次 `load()` → 断言 `#rcDoc` 的 value 仍指向第二张。

### A2 ⚠️ 客户签字的那张对账单，查询失败时会印成「本期结清 ¥0」

- **位置**：`backend/index.js:5795-5831`（`conclusionOf` 六条 SQL 各 `.catch(() => null)`）、`:5833`（`conclusionBatch` 八条 `.catch(() => none)`）
- **现象**：D1 抖一下，六条查询各自变 `null`，`num(null)` 是 0，于是「期末应收 = 0 − 0 + 0 − 0 = **0 元**」。这句话会原样出现在：`/recon-print`（客户签字确认的对账单）、`/statements-print`（批量对账）、`/statement-ack`（客户手机上的「我这边记您还欠 ¥0」）、`/track`。客户看到「不欠了」就不打款；老板看到「本期无往来」，以为早就结清了。**全链路没有一处提示「没算出来」。**
- **改法**：`.catch` 里置 `fail = true`（或收集失败条数），任一条失败就 `return null`；五个调用点判断 `null` 时显示「这一家这次没算出来，稍后再看」（客户页）/「X 家没算出来，已跳过」（批量页），**绝不回落成 0**。批量版把失败的家数单独列出来告诉老板。
- **代价**：中，约 60–80 行（5 个调用点各加一段分支）。
- **验证**：`test-ledger.mjs` 加一段——把某一家的 `orders` 临时改名（或在测试里直接调用结论函数并故意让其中一条失败）→ 断言接口返回的是 `null/错误`，页面里出现「没算出来」，且**不含**「¥0.00」结论句。

### A3 ⚠️ 批量对账失败 → 告诉老板「账是清的」，还给了能一键复制的对外文案

- **位置**：`backend/index.js:3615`（`.catch(() => ({ results: [] }))`）、`:3658`（「没有欠加工费的客户，账是清的。」）、`:3664`（仍 `ok: true`、HTTP 200）
- **现象**：每月点「批量对账」，那条 `GROUP BY` 一失败就被吞成空表 → `rows = []`、`count: 0`、`total: 0`，页面显示**「没有欠加工费的客户，账是清的。」**，而且这句话进了 `all_text`——那是专门给人复制粘到微信群的。老板据此判断这个月不用催款，直接关页面：**这个月的应收就没人管了**，还可能把「账是清的」转发出去。
- **改法**：`aggR` 的 catch 里置 `aggFail = true`，随后 `return c.json({ ok: false, error: '欠款名单没查出来（数据库刚抖了一下），先别当成没欠款，过一会儿点一次' }, 503)`；`mNewR` / `sentR` 失败时对应句子降级为「本月新增：没取到」，不静默丢句。
- **代价**：小，约 12 行。
- **验证**：`test-web-pages.mjs` 加断言——页面脚本遇到 `ok:false` 要显示 `error` 而不是「账是清的」；后端返回体里 `count === 0 && ok === false` 时不许带 `all_text`。

### A4 ⚠️ 网页「记支出」把分类的**数字 id** 写进了账里（第 20 轮 C1 我引入的）

- **位置**：`backend/index.js:8841`（下拉 `<option value="${esc(c.id)}">${esc(c.name)}</option>`）、`:8871` 附近 `doExp` 取 `el('exCat').value`、`:13860`（`POST /expenses` 收的 `category` 是**名字**）
- **现象**：实测往 `/expenses` 发 `category:'39'`，流水落库后 `cat_text` 显示 **`39`**。结果：首页「本月支出」按分类分组出现「39」「40」「41」；`/expense-compare`、经营报表的分类明细、「房租/工资/水电」这些名字全变数字。**这是我这轮要修的第一件事**（上一轮加「快速记一笔」时把 id 当名字用了）。
- **改法**：下拉的 `value` 改成 `esc(c.name)`（与 `/pc`、小程序一致），提交前再取一次名字；同时后端 `/expenses` 加一层兼容——如果 `category` 是纯数字且能在 `categories` 里查到，就换成名字（防止已有一点脏数据继续扩散）。另外写一条一次性修正：把 `ledger.category` 里「纯数字且能对上 categories.id」的行改回名字（`UPDATE ... WHERE category GLOB '[0-9]*'`），并 `noteFail` 记一笔。
- **代价**：小，约 15 行（含数据修正）。
- **验证**：`test-web-pages.mjs` 断言 `/desk` 页面源码里 `exCat` 的 option value 是 `c.name`；再真发一笔（分类「水电」）→ `/flows` 最新一条 `cat_text === '水电'`；跑一遍修正后 `SELECT count(*) FROM ledger WHERE category GLOB '[0-9]*'` 为 0。

### A5 报价单客户页：提交失败后按钮永久变灰，提示却让「请再点一次」

- **位置**：`backend/index.js:13166-13180`（`decide()`）
- **现象**：客户点「✓ 这个价可以」，网络一抖或后端 500，提示「网络不太好，请再点一次」——但两个按钮在第一行就被 `disabled = true` 了，**再也没有任何一处恢复**。客户点不动，只能怀疑自己手机坏了，或者干脆不回。这是客户侧唯一入口。
- **改法**：两个失败分支里恢复 `disabled = false`；更干净的做法是只 disable 被点的那个，`.finally` 里统一恢复。
- **代价**：小，约 4 行。
- **验证**：`test-web-pages.mjs` 断言页面脚本里「失败分支包含 `disabled=false`」；真请求——把 `t` 改错让后端 403 → 页面提示失败后按钮仍可点。

### A6 `/track`：欠款总额查不出来时静默退回「只算最近 40 单」，连提示一起消失

- **位置**：`backend/index.js:3720-3721`（`pays` 失败吞成 `[]`）、`:3731-3734`（`allAgg` 失败回落 40 单加总）
- **现象**：客户打开进度链接，顶部大数字变小（老单没算），而用来提示口径的 `allCount > docs.length` 两端同时退化 → **「（下面只列最近 40 单）」这句话也消失了**，客户完全看不出少了，可能截图来质问「我明明还欠 8 万」。`pays` 失败时每张单显示「未收 全额」，与顶部数字自相矛盾。
- **改法**：`allAgg` 为 `null` 时总额位显示「—（暂时没算出来）」，并**固定**显示「欠款总额没取到，下面只列最近 40 单」；`pays` 失败时该单写「收款记录没取到」，不写「未收 全额」。
- **代价**：小，约 15 行。
- **验证**：`test-web-pages.mjs` 断言页面里有「没算出来」分支；正常数据下断言「共 N 单 · 合计 X」仍在。

### A7 年度回顾会印出「催完收回 0 元（一分没回）」

- **位置**：`backend/index.js:18217`（6 条查询全部 `.catch → null`）、`:18249`（据此下结论）、印在 `:18287` 的 `/year-review-print`
- **现象**：`dunR` 失败 → 「催款催了 0 家共 0 次」；`inR` 失败 → **「催完收回 0 元（一分没回）」**；`custR` 失败 → 「一共做了 0 家客户的 N 单活」（自相矛盾）。这是给老板和家人看的年度总结，白纸黑字否定了老板一整年的催款工作，而他没有任何线索知道这是数据库抖了一下。
- **改法**：任一查询为 `null` 时，对应那句话**整句不出**（现有都是 `if (duns.length)` 这类条件句，把条件改成「取到了且非空」），页头加一行「本次有 N 项没查出来，这几句没算」。
- **代价**：小，约 15 行。
- **验证**：`test-web-pages.mjs` 断言 `/year-review-print` 里不含无条件出现的「（一分没回）」，且页面含「没查出来」兜底文案。

### A8 月结归档里「预收/预付」失败按 0 存，**永久**记错家底

- **位置**：`backend/index.js:4851`（`advLeftAt(...).catch(() => ({ in: 0, out: 0 }))`）、`:4891-4897`（`saveArchive` 落库）
- **现象**：`monthSnapshot` 六项里，`aggSql` / `arApLeftAt` / `debtLeftAt` / `plOf` 失败都会抛（有人看见），唯独预收预付被吞成 0。于是 `net_worth` 少了这一块，被 `saveArchive` 写进 `month_archive`——**永久快照**，月报、年报、家底走势都读它，事后没有任何痕迹能看出这个月少算了。
- **改法**：去掉这个 `.catch`，让它和另外 5 项一样抛；失败时月结整体失败并回「这个月的家底没算全，先别归档」，用户重试即可（归档本身幂等）。
- **代价**：小，约 2 行。
- **验证**：`test-ledger.mjs` 加一段——断言 `monthSnapshot` 里 `advLeftAt` 调用**没有** `.catch`（静态断言），并在脏库上跑一次月结确认失败会明确报错。

### A9 删借款时「查流水」失败 → 绕过月结锁，流水还没进回收站就被硬删

- **位置**：`backend/index.js:4449-4450`（`DELETE /debts/:id` 两条 `.catch(() => ({ results: [] }))`）、`:4424`（`PATCH` 的「已还过钱不许改本金」护栏同样靠 `.catch(() => ({ n: 0 }))`）
- **现象**：要判断这笔钱在哪些月份过账，靠的就是这两条查询。失败时月份列表为空 → `anyMonthLocked` 返回 `null` → **已结账月份的账照样被删**；同时 `intoTrash` 遍历空数组，流水一条都没备份，紧接着 `DELETE FROM ledger WHERE ref_type='debt'` 硬删。结果：某月报表数字变了，明细没了，回收站里也没有。`PATCH` 那侧同理，护栏形同不存在。
- **改法**：三处 `.catch` 全部删掉让它抛——查询失败宁可回「没删成，再试一次」，也绝不绕过月结锁。
- **代价**：小，约 3 行。
- **验证**：`test-ledger.mjs` 加静态断言——`/debts/:id` 的 DELETE / PATCH 段内出现 `.catch(() => ({ results: [] }))` 即报红。

### A10 `/pc` 把英文异常原文端给老板看

- **位置**：`backend/index.js:9619`、`:9820`（`dl()` / `xl()` 的 catch），`msg('下载失败：' + e, false)`
- **现象**：只判 `d.ok` 不看 `r.status`。Cloudflare 层回 502/504/524 的 HTML 错误页时，`r.json()` 直接 reject，页面打出 **`下载失败：SyntaxError: Unexpected token '<', "<!DOCTYPE"... is not valid JSON`**。老板看不懂，也不会想到「再点一次」——而这恰好是导出 Excel 最容易超时的时候。
- **改法**：照 `/desk` 的 `errText()` 抄一个 `/pc` 版——`SyntaxError` / `Failed to fetch` 一律显示「服务器没回应（可能超时了），过一会儿再点一次」，其余才拼原文。
- **代价**：小，约 10 行。
- **验证**：`test-web-pages.mjs` 断言 `/pc` 页面含 `function errText(` 且不含裸的 `'下载失败：' + e`。

### A11 打印抬头在数据库抖一下时会印成写死的「加工厂」

- **位置**：`backend/index.js:6784-6790`（`getTitle` 的 `catch` 返回 `title: '加工厂'`）
- **现象**：对账单、加工单、工资单、报价单、年报的抬头全走它。失败时静默印一个像真厂名的默认值，客户拿到对账单会问「这是你们吗」，而老板手机上一切正常——没有任何提示说抬头没取到。
- **改法**：失败时返回 `title: ''` 并把失败标记透出去，打印页抬头位显示「（厂名没取到，重开一次）」，不要写死一个像真的厂名。
- **代价**：小，约 5 行。
- **验证**：`test-web-pages.mjs` 断言打印页在 `title` 为空时显示兜底文案；`check.mjs` 加断言禁掉 `title: '加工厂'` 字面量。

### A12 发工资：「这个月还没记工」被报成「都已经发过了」

- **位置**：`backend/index.js:3367`（`if (!done.length) return { error: '这几个人这个月的工资都已经发过了' }`）
- **现象**：`due` 来自当月 `wage_records`；当月没记工、或应发被扣成 ≤0 时循环里 `continue`，`done` 为空却报「都已经发过了」。老板以为自己两个月前就发过了，实际是**这个月一笔工都没记**——该补记工的事被一句假话盖住。
- **改法**：`done` 为空时区分原因——`paid_rows.length` 有值 → 说「都已经发过了」；否则说「这个月还没记工（或应发被扣成 0），先去记工再发」。
- **代价**：小，约 8 行。
- **验证**：`test-web-pages.mjs` 加一段——干净库上不记工直接发工资 → 返回的错误文案含「还没记工」，不含「都已经发过了」。

### A13 `/desk` 的「记支出」现在等于让老板娘把付给供应商的货款记成费用（账会双算）

- **位置**：`backend/index.js:8841`（支出分类下拉是 `/categories` 的 `out`，含「采购 / 辅料 / 材料」）、`:8871`（`doExp` → `POST /expenses`）；对比 `POST /payables/:id/pay`（`backend/index.js:13754`）才是「付货款」
- **现象**：老板娘网银付了 2 万材料款，在 `/desk` 记「支出 → 采购 20000」。结果：现金少了 2 万（对）、**费用多了 2 万**（材料本该进订单成本）、**应付那张单一分没减**（欠款虚挂）。月底 `/cash-bridge` 的 `ap` 行、`/ar-summary`、催款清单全都对不上；如果她在小程序又付一次，就是双份。页面上没有任何提示。
- **改法**：`/desk` 的「记支出」加一个 tab「付供应商」→ 列出 `GET /due-schedule?type=ap&limit=N`，行内一个「付了」→ `POST /payables/:id/pay`。同时对「采购 / 材料 / 辅料」这类分类加一句提示：「这笔是付某张欠款单吗？→ 用上面那个「付供应商」，别记成支出」。
- **代价**：中，约 70 行（表格样式可照抄「该催的钱」）。
- **验证**：`test-web-pages.mjs` 加一段——`/desk` 页面含 `付供应商` / `/payables/` / `/due-schedule?type=ap`；真请求付一笔 → `/ap-summary` 的未结金额减少、`/expenses` 条数不变。

## B 组：高效（12 条）

> 行数是按「3000 单 / 8000 流水 / 1200 应付」估的；`SCAN orders` 这类结论都用 `EXPLAIN QUERY PLAN` 实测过。

### B1 ⚠️ `/desk` 只要标签页开着，就每分钟把整页 7 个请求重跑一遍

- **位置**：`backend/index.js:9099` `setInterval(function(){ if(!document.hidden && K) load() }, 60000)`
- **现状**：每 60 秒 7 个请求 ≈ **5–7 万行**；开 10 小时 = 600 轮 = 3000 万行以上。D1 免费额度 500 万行/天，**标签页开着 70 分钟就打满**，之后全站变慢或报错（老板会以为是「系统坏了」）。
- **改法**：拉长到 300 秒；或加一个轻量接口 `/pulse`（`SELECT MAX(id) FROM ledger` + `SELECT COUNT(*) FROM orders`，两行）比对，变了才 `load()`。表单里已填金额时跳过（同 A1）。
- **代价**：小（300 秒 = 1 行；带 pulse = 约 25 行）。
- **验证**：`test-web-pages.mjs` 断言页面里 `setInterval` 的间隔 ≥ 300000，或存在 `/pulse` 调用。

### B2 `/kpi` 算「平均回款天数」：无时间窗、无 LIMIT 的全表 JOIN

- **位置**：`backend/index.js:22528`
- **现状**：把所有**已收款流水**和 `orders` 全 JOIN 一遍，只为算 `avg_days` 一个数。EQP：`SEARCH l USING INDEX idx_ledger_fixed` + 逐行回表 + `TEMP B-TREE GROUP BY`。8000 流水的账这里读 **约 1.2 万行**，占 `/kpi` 三分之一。

### C12 第一次在电脑上打开就被口令挡住，而网页上没有「第一次设置」

- **位置**：`/desk` 闸门（`backend/index.js:8660-8668`：「先输访问口令」+ 一条「第一次用 / 忘了口令 → /pc」）；`/pc` 只有改口令和恢复码重设（`:9160-9169`）；首次设置接口 `POST /auth/setup`（`:1160-1190`）存在、会返回一次性恢复码，但网页从不调用
- **现在**：老板娘第一次开电脑版 → 不知道口令 → 点「第一次用」→ `/pc` 要 16 位恢复码 → 恢复码在手机「我的」里 → 掏手机找 → 回电脑输 → 再输口令。从来没设过口令的，这条路直接走不通。进来之后：6 张卡全 ¥0.00、绿字「没有逾期没收回的钱 👍」、「最近没有单据」——没有一句「第一步做什么」。
- **改成**：`/pc` 加一张「第一次用：在这儿设口令」，设完把 16 位恢复码当场显示（接口已经返回），附「抄纸上放抽屉，忘了只有它能救」；空账套时把 6 张卡换成「三步开账」。
- **代价**：中，40–50 行。
- **⚠️ 需要你拍板**：如果部署配了 `INSTALL_TOKEN`，把「设口令」放出来必须同时要求输入安装令牌——否则谁先打开这个网址谁就成了老板。这条我建议**先做「空账套引导」，设口令仍只在部署时用令牌完成**。

## 有意不做（说清理由，别再提）

1. **网页端做「改单 / 删单 / 批量录入」主入口**——手机才是录入主入口，网页做全量 CRUD 等于维护两套校验，风险远大于收益。只做「刚记错了撤掉」（C6）。
2. **网页端做「一键解锁已结账月份」**——锁就是用来防手滑的。C8 只做「看能不能结」。
3. **`/guide` 改静态站 / 分页**——现在 30 KB 一次性加载，`br` 压完约 10 KB，还带 ETag 304；改了收益极小。
4. **把 `/desk` 做成仪表盘图表（趋势线、饼图）**——老板要看的是「该催谁、该付谁」，不是图。且图会让 `/desk` 从 28 KB 涨到 100 KB+。
5. **暗色模式**——用的人少，还要给 45 处内联样式各配一套。
6. **给客户开在线支付 / 收款码**——需要微信支付商户号（企业主体），不在本轮。
7. **多语言**——客户和老板都是中文。
8. **员工独立网页端**——员工在车间用手机，网页给员工做等于把权限问题放大。
9. **D1 换 Postgres / 加 Redis**——现在最贵的一次点击 7 万行，B 组做完能降到 1.5 万行上下，远不到需要换存储的程度。
10. **把 `/pc` 的 Excel 模板改成网页在线表单**——Excel 对会计是刚需（她还是要在 Excel 里算），改成网页等于让她录两遍。
11. **`/desk` 加「本月利润走势图」**——`/year-review-print` 已有柱图，重复。
12. **给打印页加二维码（扫码回到线上单据）**——需要外网可解析的短链 + 客户教育，收益不明。
13. **前端 `index.js`（10,464 行）/ `index.wxml`（3,866 行）拆分**——这是小程序侧的欠账，不在「网页端」范围，且没有 UI 自动化测试网兜底，拆了风险大。
