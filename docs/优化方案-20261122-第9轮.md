## B 组：事务原子性（多写点接口改成 D1 原子 batch）

现在这些接口是「多次独立 await」，中途进程挂掉就留半截数据。D1 的 `db.batch` 是原子的，一次改完。

| # | 接口 | 位置 | 现在的写法 | 改法 |
|---|---|---|---|---|
| B1 | `POST /advances` | `:6355-6392` | INSERT 主表 → INSERT ledger → catch 里 DELETE 主表 + opRelease（手工补偿，补偿本身可能失败 `:6385`） | 一次 `db.batch([insert advances, insert ledger])` |
| B2 | `POST /loans` | `:6606` | 同 B1（补偿在 `:6629`） | 同 B1 |

| B4 | `POST /import-rows` / `importRows` | `:4473` → `:12760-12800` | 每行一个 INSERT，循环内无 batch；500 行导一半失败 → 前 N 行已入账、接口报错 | 每 50 行一个 batch，响应带「成功 N 行」 |
| B5 | `POST /payroll/pay` | `:2662-2738` | `wage_pays` 插入与 `ledger('工资')` 插入两次独立 await → 工资单发了现金没扣 | 一个 `db.batch`，守卫条件放进 batch 的 `SELECT…WHERE` |

## 有意不做的（附理由）

- **不做全局 mass-replace SQL 口径**：`ref_type NOT IN (...)` 66 处、`COALESCE(written_off,0)` 227 处 —— 上一轮已定：只加断言防护，不做批量替换（回归风险高，收益低）。
- **不动已经正确的乐观锁/超卖守卫**：`receive/pay/apply-advance/loans/material-moves/writeoff` 的 `WHERE … <= amount + 0.005` 是全站最值钱的部分。
- **不删 `ENV_ALL` 那 30+ 处**：一次改 30 处语义风险高，本轮只加注释 + 抽函数的准备，不做全量替换。
- **公开打印页签名机制保留**：只调整校验顺序（放到模块/封账检查之后），不重写签名。
