## A 组｜鉴权与越权（最高优先：能改别人的账 / 能爆破口令）

### A1 五个公开 auth 接口无爆破限流，可无限猜老板口令
- **位置**：`backend/index.js` `/auth/staff`（约 :1334）、`/auth/staff-off`（:1358）、`/auth/demo`（:1378）、`/auth/demo-state`（:1402）、`/auth/demo-builtin`（:1410）；公开早退分支约 :1605 `path.startsWith('/auth/')`。
- **机制**：这 5 条都走公开早退（无鉴权），内部用 `verifyKey(mainDb, b.key)` 校验老板口令，但全文 `authLocked/authFail` 只出现在 setup/change/find-book/recover-code/recover/super/super-state 七处。口令不对返回标准「口令错误」文案 → 既可无限试，又是口令 oracle。第 11 轮 A5 只补了 super/super-state。
- **改法**：5 条统一加 `const ip = clientIp(c); const wait = await authLocked(mainDb, ip); if (wait) return 429 tooMany(wait)`；校验失败 `authFail(mainDb, ip)`、成功 `authOk(mainDb, ip)`。抽一个 `withAuthProbe(c, db, fn)` 包装避免再漏。
- **代价**：极低（复用现成三个函数）；需回归正常设员工/演示口令与错口令计数。

### A2 演示账禁权限是 fail-open
- **位置**：`backend/index.js:1336` 与 `:1359`：`try { if (await isDemoBook(c)) return denyDemoPerm(c) } catch (e) { /* 判断不出来就不拦 */ }`。
- **机制**：判断抛错即放行 → 演示账里仍能设员工/改权限，正是第 9 轮专门堵死、审核会卡的那件事。与已改 fail-closed 的 `attRefVisible` 相反。
- **改法**：catch 里改成 `return denyDemoPerm(c)`（判断不出来就当演示账拦），并 `noteFail(e,'演示账判定')`。
- **代价**：极低；需在「settings 表缺失」的极端场景确认不会误拦真账（可只对 `isDemoBook` 的首次判定 fail-closed）。

### A3 员工可写的三条按 id 路由无归属闸，可给别人的单收款/改状态/付款
- **位置**：`backend/perm-rules.mjs:6-7` 白名单 `/^\/orders\/\d+\/receive$/`、`/^\/orders\/\d+\/status$/`、`/^\/payables\/\d+\/pay$/`；`backend/index.js` `/orders/:id/receive`（约 :11910）、`/orders/:id/status`（:12275）、`/payables/:id/pay`（:12342）都只 `SELECT * FROM orders/payables WHERE id=?`。
- **机制**：第 9 轮只给 GET detail/processes/attachments 补了 `orderVisible/payableVisible/scopeOwn`。`staff_scope='own'` 下员工猜 id 就能操作别人的单，钱记到别人账上。
- **改法**：三条在查出行后各加 `if (!(await orderVisible(c, db, o))) return 404`（payable 用 `payableVisible`）；`status` 也接同一闸。文案与「不存在」一致，不泄露单据存在性。
- **代价**：低；own-scope 员工跨单操作会被拒（预期）。补 3 条「员工猜别人 id 得 404」断言。

### A4 公开打印页签名永久有效，含毛利的月报一次拿到永久可看
- **位置**：`sigBook(...)` 未传 exp 的调用点：`backend/index.js` handover :3677、order-print :4728、report-print :4770、recon :5442、quote :11752/:11799、ack :15171/:15214、yearreview :16568、year-close :16870、year-book :16914、year-open :17051、health :18284；`linkExpired` 只在 :3225/:3461/:3743 校验。
- **机制**：第 10 轮只给 statement/track/payroll 加了 exp。`/report-print` 页面直接印「材料·外协成本 / 成本合计 / 净利 / 净利率」（约 :4812 起）→ 拿到一次链接永久能看这份含毛利月报，转发出去客户能看到你的底价。
- **改法**：给全部公开页统一 `linkExpOf(ttl)`（打印类复用 `LINK_TTL.statement=7d`，quote/ack 用 7d）并在校验处加 `linkExpired(exp)`；存量链接立即失效需重发。优先处理 report-print / recon-print / quote-print 三个含钱字段的。
- **代价**：中——所有旧链接失效，需提示用户重新生成；回归要覆盖「过期链接打不开」。

### A5 对账确认链接：month 不在签名内 + POST 可无限重放（假确认）
- **位置**：`backend/index.js` `/statement-ack`（GET 约 :15163、POST :15206），`sigBook(...,'ack:'+type)` 不传 exp，`month` 只是 query；POST 直接 `INSERT INTO statement_log`，无去重无 `ack_at` 判定。
- **机制**：拿到链接的人改 `month` 就能看该客户任意月份对账（含未结单据/金额），永不过期；转发链接可对同一 party/month 反复提交「对得上/对不上」，`/disputes`、`/statement-acks` 当真。
- **改法**：签名数据含 month：`sigBook(mainDb, BOOK, party, 'ack:'+type+':'+month, linkExpOf(LINK_TTL.statement))`；GET/POST 都校 `linkExpired(exp)`；POST 用 `db.batch` + `WHERE NOT EXISTS(SELECT 1 FROM statement_log WHERE party=? AND type=? AND month=? AND ack_at IS NOT NULL)`，`changesOf` 为 0 返回 409。
- **代价**：中——存量确认链接失效、`conclusionOf` 查询失败的页面也要一并处理（见 A6）。

## B 组｜账务正确性与「假成功」（年报/报税/自检算错或静默放行）

### B1 selfCheck 查询失败照样 ok:true（账实自检失效）
- **位置**：`backend/index.js` 约 :17985：`jobs.map((x) => x.catch((e)=>{ noteFail(e); return null }))`，随后把 null 当 `[]`/0 继续比较。
- **机制**：15 条对账查询任一条 D1 超时/锁错失败，对应结果变 0，「发现坏账/重复收款/孤儿流水」的最后一道网静默放行。
- **改法**：`await Promise.all(jobs)` 不逐条吞；任一 reject 返回 `{ok:false, error:'自检查询失败'}` 并让 scheduled 告警；不允许 null 参与比较。保留 issues 截断逻辑。
- **代价**：D1 抖动会从「0 问题」变失败/告警——这是对的；加「注入失败查询不得 ok:true」测试。

### B2 yearBook 吞错报 0 + 口径与 year-summary 分叉 + 催款回收虚高
- **位置**：`backend/index.js` 约 :16404 `jobs.map(j=>j.catch(...return null))`、:16433 `advLeftAt.catch(()=>({in:0,out:0}))`、:16459 `ok:true`；裸 `COALESCE(SUM(price))` :16373；利润 `income-mat-exp-adj` 未减 writeoffs；`yearReview` :16486「少赚」又一套口径；`/dunning-year` :14968 首次催款后所有回款都算「催完收回」。
- **机制**：查询失败即变 0 仍 ok；REAL 求和与 `SUM_MONEY` 整数分差几分到几元；催款回收无上限、无按单去重，avg=recovered/times 虚高。这些数进 tax-pack 总览和老板建议。
- **改法**：Promise.all 不吞错；裸 SUM 改 SUM_MONEY；利润减同期 writeoffs（按 `COALESCE(month,substr(created_at,1,7))`）；催款按 `ref_id` 建 firstDun，回款落在 `[dun_date, 争议解决日]` 且按 ledger.id 去重，avg 按催款事件计。
- **代价**：改口径后历史年报数字微变（需在 README 注明）；D1 抖动时年报由 0 变 500（前端可重试）。

### B3 tax-pack 折旧/摊销/预提恒为 0，资产负债表漏预收预付
- **位置**：`backend/index.js` 约 :17087-17090 `FROM ledger WHERE cash=1 ... ref_type IN ('amort','dep','accrual')`；资产负债表 :17128。
- **机制**：摊销/折旧/预提记 `cash=0`（见 `ADJ_EXP_WHERE`），`cash=1` 过滤让它们永远查不到 → 报税材料里这三项全 0，与 yearBook 净利对不上；资产合计只算 `cashEnd+ar_end`，漏预付（资产）/预收（负债）。
- **改法**：`17090` 改 `WHERE ${ADJ_EXP_WHERE} AND substr(created_at,1,4)=?`；资产负债表按 yearBook 同口径把 `advOutEnd` 计入资产、`advInEnd` 计入负债、权益用 `netEnd`。
- **代价**：历史导出数字变化，需通知会计重导；加断言「tax-pack 净利 == year-summary 净利」。

### B4 收款 `settle:true` 时负数金额「假装成功」
- **位置**：`backend/index.js` 约 :11929 `if (a <= 0 && !settle) return 400`，`woAdd = settle ? round2(leftOrder - Math.min(a,leftOrder)) : 0`。
- **机制**：`settle:true` + 负数 `a` 不被拦；`woAdd` 超额被守卫挡住、takeIn 又不 >0，最终返回 ok 但账上什么都没记——用户以为结清了。
- **改法**：无论 settle 与否都要求 `a >= 0`，且 `settle` 时 `a + WoAdd <= leftOrder + 0.005`；不满足 400。付款侧同口径核查。
- **代价**：极低；补「负数 settle 得 400 且账未变」测试。

### B5 edit-requests 审批双重 TOCTOU + 金额字段无类型校验
- **位置**：`backend/index.js` 约 :18490-18526：预查 status、拼 SET、UPDATE 无 rev/status 守卫，`sets` 只白名单字段名不校验值。
- **机制**：并发两次审批（或审批+驳回）都过预查，各自写业务表、审计记两条「同意」；`price:"abc"` 可写进 REAL 列，后续求和变 0/NaN。
- **改法**：整段 db.batch：首条 `UPDATE edit_requests SET status='ok'... WHERE id=? AND status='pending'`，业务表 `WHERE id=? AND COALESCE(rev,0)=?`（CAS），`changesOf` 为 0 返 409；金额/qty 用 `numStrict` 校验，非法 400。
- **代价**：并发第二次变 409（正确）；补「双审批只生效一次」「price=abc 被拒」测试。

### B6 预收/预付 ledger.ref_id 用 `(SELECT MAX(id) FROM advances)` 绑错单（并发）
- **位置**：`backend/index.js` 约 :6994-7000。
- **机制**：batch 第二条取全表 MAX(id)，不是刚插入那条。两个 isolate 并发各插预收时，A 的流水可能挂到 B 的 advance 上 → `advLeftAt`/核销/家底全错。第 9 轮 A6 已在另外 4 处改成 MAX(id)，这里是同一坑的漏网处。
- **改法**：用 `last_insert_rowid()`（同 batch 顺序执行、取本连接刚插入的 id）或应用侧生成显式 id 两条都 bind；补并发断言 `ledger.ref_id == advances.id`。
- **代价**：低；D1 支持 `last_insert_rowid()`。

### B7 /writeoffs 月份筛选与 yearBook 仍用 substr(created_at)，忽略 month 列
- **位置**：`backend/index.js` 约 :21880（列表）、:21896（删除路径）；`yearBook` 约 :16390/:16395；对比 :15577/:17211 已用 `COALESCE(month,substr(...))`。schema 已有 month 列与 idx_writeoffs_m（第 10 轮 C2）。
- **机制**：补录/改月的核销按 created_at 归属，不出现在正确月份报表，坏账/豁免合计错。
- **改法**：三处统一 `COALESCE(month,substr(created_at,1,7))=?`（yearBook 用 1,10 视其口径对齐）。
- **代价**：历史补录记录「移动」到正确月份，旧月报数字变；性能反而更好（走索引）。

### B8 year-open 无幂等键 + 打印链接无 exp 且实时重算
- **位置**：`backend/index.js` 约 :17004-17024（POST）、:17040/:17053（打印）。
- **机制**：`confirm:true` 可随时重算覆盖期初，无 client_id/CAS → 网络重试产生两条审计、两次不同 created_at；打印签名仅 `yo:${y}` 无 exp 且每次打开实时算，旧凭据链接在老板改期初后显示新数字，纸面凭据与当时不符。
- **改法**：POST 走 `opClaim(client_id,'year-open:'+y)` 并进 db.batch；签名带 created_at 快照 + exp，或写快照表按 ID 渲染。
- **代价**：旧链接失效需重发；confirm 要带新 client_id（前端同步）。

### D5 首次设口令连点两次 + 卸载后仍 setData
- **位置**：`frontend/pages/index/index.js:7019-7046`（原生 wx.request、无 busy 锁、无 _dead 检查）。
- **机制**：两个并发 setup，后端 ON CONFLICT 让第二个返 400，但两个回调都写 storage/c.done/loadMe；一个弹新恢复码、一个写 key_err，恢复码可能被错误态覆盖 → 用户拿不到恢复码。
- **改法**：加 `if (this._kBusy) return; this._kBusy=true`，所有分支先复位；改走 `this.req({ once:'auth-setup' })` 或带 client_id；仅 d.ok 分支写 storage/弹码；加 `_dead` 守卫。
- **代价**：中——首次登录敏感，回归正常设口令、错 install_token、过期补发三条。

### D6 amtOf 静默吞非法金额（qty/rate/residual/tax），与「必须 toast 拦下」冲突
- **位置**：`frontend/pages/index/index.js:342-345`（`amtOf` 默认 0/1/5），:9142 pw_qty/rate、:9277 residual_rate、:7218 rate/term、:8746 tax；对照 `DEPLOYMENT.md:1303`。
- **机制**：金额字段多数已有 >0 guard，但 qty/rate/residual/tax 这类输入 `abc` 被静默换成默认值，产生错误折旧/工资/数量，用户无感。

- **代价**：中——历史「空代表 0」习惯要保留兼容。

## E 组｜前端弱网与竞态

### E1 分组页/展开单据失败被显示成「没有欠款」/「正在取」

### E2 `_tabReqSeq = {}` 导致切账后 loadMe 回调全被丢

### E3 全局请求无 `_dead` 守卫（seq=0）
- **位置**：`frontend/pages/index/index.js:546-553`（守卫只在 rseq truthy 时包）、`:2686-2692`（`_globalLoad` 把 `_tabReqSeq=0`）、`:1018 onUnload`。
- **机制**：dashboard/me/accounts 等首屏请求 success/fail 无 `_dead` 检查，卸载后仍 setData，可能把旧账数据写进新页面实例。
- **改法**：把 `_dead` 检查移到 rseq 判断之外，对所有请求生效。
- **代价**：低；确认无「卸载后仍需完成」的链路（flushPending 走原生请求，不受影响）。

### E4 经营看板把含应计调整的支出标成「现金成本」
- **位置**：`frontend/pages/index/index.js:6308`（`d.cost_cash = expense_cash + fixed_cash`）、`index.wxml:1724`、后端 `/profit-compare` :10403（`expense_cash` 已含 accAdj）。
- **机制**：现金口径与应计口径混用，标签误导老板判断「这月活值不值」。
- **改法**：直接显示后端 `cash_profit`/`accrual_profit` 及 basis，删本地 cost_cash 重算；若展示成本行，标签改「现金+应计调整后成本」。
- **代价**：低（纯展示）。

## F 组｜CI / 迁移 / 测试门禁（发布安全与回归可信度）

### F1 CI 回滚后不复核，可能把坏版本留在线上
- **位置**：`.github/workflows/deploy.yml:580-605`（回滚 step）。
- **机制**：`wrangler rollback` 退出 0 就宣称成功，之后不 fetch /version 复核 commit；最终一致性/回错版本时 CI 仍绿。
- **改法**：回滚后复用 :472-489 的 node fetch 轮询 /version.commit 不再是 `${{ github.sha }}`（或等于回滚前记录的上一 released commit），最多 60s，否则 exit 1 + summary。
- **代价**：一次回滚多等数秒；要处理 eventual consistency。

### F2 INSTALL_TOKEN 写入失败只 warning，安全门静默降级
- **位置**：`.github/workflows/deploy.yml:440-454`（`|| { echo ::warning; exit 0 }`）。
- **机制**：secret 已配但 `wrangler secret put` 失败时 job 继续绿，后端退化为只 IP 限流。
- **改法**：secrets 非空时移除 `|| exit 0` 让 step 真失败；加 post-deploy 未授权 /auth/setup 探测（不真首设口令，先确认库里无 access_key）。
- **代价**：网络抖动会让部署红（可接受）。

### F3 schema-baseline 解析器不识引号 + 只比列名
- **位置**：`scripts/check.mjs:209-220, 279-317`；`backend/schema.sql:451` `modules TEXT ... DEFAULT 'ar,ap,exp,import,contact,asset'`。
- **机制**：按圆括号深度拆逗号但不跟踪引号，DEFAULT 里的逗号被拆成假列 `ap/exp/...`；check 和 baseline 同错所以绿。且只比列名，type/default/整表删除都不查（`if (!now) continue`）。
- **改法**：复用 `server/d1.mjs completeColumns()` 的 quote-aware splitter；baseline 升级为 `{type,notnull,dflt,tablePresent}`，`--update-baseline` 重生成；type/default 变化需显式批准（白名单防 SQLite 类型规范化误红）。
- **代价**：baseline 一次性 churn。

### F4 d1-migrate 无超时 + 文本匹配 migrations 记录
- **位置**：`scripts/d1-migrate.mjs:48-56, 93-115`。
- **机制**：spawnSync 无 timeout，单条远程命令卡住拖满 6h；`q.text.includes(f.name)` 判「跑过了」，wrangler 回显含文件名就误判 skip → 老库缺列缺索引、上线 500。
- **改法**：spawnSync 加 `timeout:120000` + 总 deadline；用 `--json` 或 `SELECT name` 精确匹配行判记录，查询结果写日志。
- **代价**：需核 wrangler --json 格式；慢 D1 可配 120-300s。

### F5 本地/线上 D1 严格性不同，本地绿不能推线上
- **位置**：`server/d1.mjs:31-37`（100 参数/100 语句/100KB 上限）、`server/main.mjs:305-315`（自动 ensureSchema + 9 本账、无 APP_COMMIT）对比 `backend/wrangler.toml` 绑定。
- **机制**：本地自动建表补列、构造 9 本账；线上只有已绑定库、老库靠迁移。引用未绑定 binding 或超 D1 限额的 SQL 本地过、线上 500。
- **改法**：CI 加一步 `wrangler d1 execute --local` 对关键 write batch 跑 strict（`FACTORY_D1_STRICT=1`）；check.mjs 静态断言 `env.<BINDING>` 都在 wrangler.toml 里。
- **代价**：会暴露历史宽松 SQL，需分批修。

### F6 写接口覆盖只证明「不 5xx」，400/404 也算过且无写后读
- **位置**：`scripts/test-write-methods.mjs`、`scripts/test-write-coverage.mjs`（`no500 = status<500`、`alive = status<500 && !!res.d`）。
- **机制**：handler 校验失败 400、路径拼错 404、事务部分写入后返回错误都算过；195 写接口「已覆盖」是假安心。
- **改法**：按路由建 expected-status map（create 200/201、update/delete 200，负例单独测 400）；统一 `assertPersisted` 带 TAG 写后 GET 断言字段，两脚本共用、隔离清理。
- **代价**：测试时长上升；部分接口本就用 400 表业务失败，需维护映射。

### F7 check-manifest 只反查 test-*，非 test 脚本可长期没人跑
- **位置**：`scripts/check-manifest.mjs:31,47-56`；`scripts/run-all.mjs:20-31`。
- **机制**：反向只校验 `test-` 前缀；`d1-*/gen-*/check-*` 等非 test 脚本漏登记永远不红，腐烂到发布/回滚才炸。
- **改法**：全量枚举 `scripts/*.mjs`，非下划线开头脚本必须在 workflow 出现或在显式 MANUAL 白名单（注明用途），否则红；保留 CASES 三处一致。
- **代价**：加 helper 要同步登记（正是想要的门）。

### F8 INSTALL_TOKEN 文案与实现矛盾 + test-fixes3 断言假绿
- **位置**：`backend/index.js:1113`（错误文案指向「GitHub Actions 摘要里那串」）、`docs/优化方案-20261123-第11轮.md:30`（方案说生成随机 token 写 summary）vs 实际 `deploy.yml:440-454` 用预置 secret 且不打印；`scripts/test-fixes3.mjs:116,139`（`status===200||status===400`、`bv.status>=400` 也算过）。
- **机制**：首设口令报错把人指到不存在的 summary，排查方向错；test-fixes3 把 400/500 当成功，recon 真失败不红。
- **改法**：错误串改「GitHub 仓库 Settings→Secrets 里配置的 INSTALL_TOKEN」，第 11 轮方案补修订说明；test-fixes3 改严格 `eq(status,200)` + 显式负例，备份校验断言 200 且 `Array.isArray(d.skipped)`。
- **代价**：极低；注意同步任何断言旧文案的脚本（grep 未见）。
