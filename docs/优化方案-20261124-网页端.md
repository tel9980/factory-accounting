# 网页端优化方案（2026-11-24）

> 范围：`backend/index.js` 里所有 `c.html(...)` 下发的页面 —— 13 个 A4 打印/查看页、`/`（入口）、`/pc`（电脑工作台）、`/guide`（图文教程）、`/track`（客户只读对账）、`/statement-ack`（客户确认页）。共 35 处 `c.html(`，其中 13 处走 `a4Page`。
> 本文只出方案，不改代码。每条都写了「现状（含行号）/ 为什么是问题 / 改法 / 代价 / 怎么验」。

---

## 0. 现在网页端长什么样

| 页面 | 谁在看 | 主要设备 | 现状判断 |
|---|---|---|---|
| `/statement-print` 对账单 | **客户**（发链接） | 手机 90% | 手机上进得太挤，见 A1 |
| `/payroll-print` 工资单 | 员工（发链接） | 手机 | 同上 |
| `/order-print` `/quote-print` `/handover-print` 单据/报价/交接 | 客户 | 手机 | 同上 |
| `/report-print` `/year-print` `/year-close-print` `/year-open-print` `/year-review-print` 报表 | 老板、会计 | 电脑为主 | 桌面端基本没问题 |
| `/recon-print` `/health-print` | 老板、会计 | 电脑 | 同上 |
| `/statement-ack` 客户确认 | **客户**（发链接） | 手机 | 已经不错，缺提交后状态（F1） |
| `/track` 客户查进度 | **客户** | 手机 | 已经不错（移动 CSS、结论、tel 链接、每小时只记一条） |
| `/` 落地页 | 所有人 | 手机 | 够用，缺 favicon 与「已经在用」的直达（F5/F6） |
| `/pc` 电脑工作台 | 老板 | 电脑 | 功能有（导入导出/账套/员工），**但看不了账**（D 组） |
| `/guide` 图文教程 | 老板、会计 | 电脑/手机 | 27.6 KB 每次全量下发，内容不标版本 |

一句话结论：**桌面端的报表页没问题；问题集中在「客户在手机上看的那几张 A4 页」和「老板在电脑上看不到账」。**

优先级建议：**A 组（手机可用性）> D 组（电脑看账）> B 组（打印质量）> C 组（统一层与安全头）> F 组（细节）> E 组（体积）**。A 组改一处 CSS 全站生效、风险极低、受益面最大；D 组价值最高但要新写一个页面，放第二批。

## A 组：客户在手机上看打印页（P0）

### A1 打印页在手机上被 `12mm` 边距挤扁（最要紧）
- **现状**：`A4_CSS`（`backend/index.js:3804`）里 `body{padding:18px}`、`.sheet{max-width:210mm; padding:14mm 12mm}`。全仓**只有 1 个 `@media`**（`backend/index.js:3824` 的 `@media print`），**没有任何屏幕断点**。
- **为什么是问题**：手机宽 375px 时内容宽 = 375 − 18×2（body）− 12mm×2≈90.7（sheet）≈ **248px**。对账单是 7 列表格，每列约 35px，表头「本期已收」四个字在 12.5px 字号下约 50px → 必然折行，金额栏挤压到看不清。而客户 90% 是在微信里用手机点开这条链接的。
- **改法**：在 `A4_CSS` 末尾加一条屏幕断点（打印不受影响，因为 `@media print` 在后、且 `@page` 管页边距）：

  ```css
  @media screen and (max-width:760px) {
    body { padding:8px; font-size:12.5px; background:#eef0f3; }
    .sheet { padding:14px 12px; box-shadow:none; border-radius:8px; }
    h1 { font-size:19px; letter-spacing:1px; }
    h2 { font-size:13px; margin:14px 0 5px; }
    table { font-size:12px; }
    th, td { padding:5px 5px; }
    .sign { flex-direction:column; gap:10px; }
    .sign span { margin-right:0; }
    .tip { font-size:11.5px; }
    .btn { width:100%; }
  }
  ```
  改完后手机内容宽 ≈ 375 − 16 − 24 = **335px**（比现在宽 35%），7 列每列约 47px。
- **代价**：改 1 处字符串，13 个打印页 + `/statement-ack`（用 `ACK_CSS`，同样要加）自动生效。零接口改动。
- **怎么验**：Chrome DevTools 375×667 打开 5 个典型页（对账单/工资单/单据/报价/客户确认），确认①无横向滚动条 ②表头不折成两行 ③金额不被截断；再 `Ctrl+P` 打印预览确认 A4 版式与改前**像素级一致**（`@media print` 分支未被触碰）。

### A2 宽表在窄屏给一条「横着看」的兜底
- **现状**：对账单 7 列（日期/品名/数量/单价/金额/已收/未收），工资单列数更多。
- **为什么是问题**：A1 之后 47px 一列仍偏窄，尤其「已收 12,000.00」这种。
- **改法**：给宽表加 `class="wide"`，断点里 `@media screen and (max-width:760px){ .wide{display:block; overflow-x:auto; white-space:nowrap} }`；同时把**只有内部才看的两列**（「序号」「核销」）标 `class="m-hide"`，断点里 `display:none`。
- **注意**：**金额列、日期列不许隐藏** —— 对账单是给客户核对的，藏金额等于藏账。这条写进注释。
- **代价**：`A4_CSS` 加 3 行 + 各页表格加 class（5 个页面）。
- **怎么验**：375px 下对账单横向滑动能看到全部金额；打印预览里 `.wide` 不生效（仍是正常表格）。

### A3 微信里点「打印」没反应，且 12 个页面没有提示
- **现状**：`a4Page`（`backend/index.js:3838`）的按钮是 `<button class="btn" onclick="window.print()">`。微信内置浏览器不弹打印对话框，点了就是没反应。全仓只有 1 处提示：对账单页 `tip: '手机上：右上角「…」→ 发送给朋友或用浏览器打开 → 打印'`（`backend/index.js:3932`），其余 12 个打印页都没有。
- **为什么是问题**：客户在微信里点「打印/存 PDF」→ 没反应 → 以为坏了 → 打电话问老板。这是最常见的售后问题。
- **改法**：在 `a4Page` 里加一段内联脚本（一处改动，13 页生效）：

  ```html
  <script>
  (function(){
    var wx = /MicroMessenger/i.test(navigator.userAgent);
    var b = document.getElementById('pbtn'), tip = document.getElementById('pbtn-tip');
    if (wx) {
      b.textContent = '微信里打不开打印：点右上角 ··· → 在浏览器打开';
      b.onclick = function(){ alert('微信里不能打印。\n点右上角「···」→「在浏览器打开」，再点打印。'); };
      tip.style.display = 'block';
    }
  })();
  </script>
  ```
  并把按钮改成 `id="pbtn"`，`tip` 里写「也可以点这里复制链接，发到电脑上打开」+ 复制按钮（`navigator.clipboard.writeText(location.href)`，失败退回 `document.execCommand('copy')`）。
- **代价**：`a4Page` 加约 15 行；对账单页原有的那行手工 tip 删掉（避免重复）。
- **怎么验**：把 UA 改成 `... MicroMessenger/8.0` 打开任一打印页 → 按钮文案变了、点击弹说明；普通 UA → 仍是「🖨 打印 / 存为 PDF」且点了弹打印框。

### A4 金额没有千分位，大额难读
- **现状**：`money()` 直接 `toFixed(2)`，全仓 11 处 `toFixed(2)`；已有 `font-variant-numeric: tabular-nums`（`.n`）。
- **为什么是问题**：`¥1234567.89` 和 `¥12345.67` 在窄屏上肉眼难分位数，客户核对金额容易看错一位。
- **改法**：新增 `const money = (v) => '¥' + Number(num(v)).toLocaleString('zh-CN', { minimumFractionDigits: 2, maximumFractionDigits: 2 })`，打印页的金额单元格统一用它（对账单合计、工资单实发、月报各合计行）。**只在网页端用**，小程序 JSON 口径不动。
- **代价**：改 1 个函数 + 替换打印页模板里的拼接（约 20 处）。
- **风险**：千分位让数字更长 → 必须和 A1 一起上，否则更挤。
- **怎么验**：造一笔 1,234,567.89 的单，对账单上显示 `¥1,234,567.89`；`/ar` 接口返回仍是 `1234567.89`（JSON 不受影响）。

### A5 打印按钮滚一下就找不到了
- **现状**：按钮在 `.sheet` **之前**（`a4Page` 里 `<button class="btn">` 在 `<div class="sheet">` 上方），页面一滚就滚出屏幕。
- **改法**：断点里 `.btn{ position:sticky; top:0; z-index:5; }`（手机端吸顶）；或改成右下角浮层 `position:fixed; right:12px; bottom:12px; width:auto`。`@media print` 已经 `display:none`，不会打进纸里。
- **怎么验**：手机视图滚到页面中间，按钮仍在可视区；打印预览里没有按钮。

## B 组：打印出来的纸（P2，会计在用）

### B1 跨页丢表头、行被切断
- **现状**：全仓 `<thead>` 只有 3 处（工资单 `:3319` 含 thead+tfoot、对账单 `:3907`、报表一处）；没有 `page-break-inside:avoid`、没有 `orphans/widows`。
- **为什么是问题**：一张对账单超过一页时，第 2 页开始没有列名，会计得翻回第 1 页对列。
- **改法**：`A4_CSS` 加 `tr{ page-break-inside:avoid } h1,h2{ page-break-after:avoid } thead{ display:table-header-group } tfoot{ display:table-footer-group }`；给 4 个可能超一页的表格（对账单明细、工资单、年度对比、健康报告问题清单）补 `<thead>`。
- **代价**：CSS 4 行 + 4 个模板各加一行 `<thead>`。
- **怎么验**：造 60 行明细的对账单 → 打印预览第 2 页顶部有列名，没有半行被切断。

### B2 没有页码（诚实说明：做不了真页码）
- **现状**：打印页无页码、无「第几页/共几页」。
- **说明**：Chrome/Edge 只支持 `@page` 的 size/margin，**不支持 `@bottom-right{ content: counter(page) }`**（那是 Paged.js/Prince 的能力）。要在纸上印真页码只有两条路：①让用户在打印对话框里勾「页眉页脚」（浏览器自己印 URL+页码，丑但有效）②后端接 puppeteer 生成 PDF（要额外运行时，且 Cloudflare Workers 跑不了）。
- **改法（不做真页码，做替代）**：每份末尾 `.foot` 固定印「单位名 · 单据类型 · 生成时间 · 数据截至 X」，跨页时至少有归属；并在页面 tip 里加一句「要页码就在打印对话框里勾『页眉和页脚』」。
- **代价**：5 个模板加 `.foot` 一行；`A4_CSS` 加样式。
- **怎么验**：打印预览最后一页有这行字。

### B3 黑白打印/省墨模式下合计行看不出来
- **现状**：`th{background:#f0f2f5}`、`.total td{background:#fafafa}`。省墨模式或黑白激光打印时浅底可能不出，合计行和普通行没区别。
- **改法**：`th{ border-bottom:2px solid #333 }`、`.total td{ border-top:2px solid #333; border-bottom:2px solid #333 }`，并加 `-webkit-print-color-adjust:exact; print-color-adjust:exact;`（保证勾了「背景图形」时底色出得来）。
- **怎么验**：打印预览勾「黑白」+ 不勾「背景图形」，合计行仍能靠双线认出来。

### B4 一次只能打一家对账单
- **现状**：`/statement-print` 一次一家（`?party=…`）。
- **为什么值得做**：老板月底要给 20 家发对账单，现在是「小程序里点 20 次 → 20 条链接 → 20 次打开 → 20 次打印」。
- **改法**：新增 `/statements-print?m=YYYY-MM&parties=a,b,c&t=…&x=…`，内部循环渲染多张 `.sheet`，每张之间 `page-break-after: always`；签名串用 `bulk:<month>:<parties 排序后 join>`，有效期同样 7 天（`LINK_TTL.statement`）。配套 `/statements-print-link`。渲染逻辑从 `/statement-print` 抽成 `statementSheet(db, party, from, to, t)` 复用（现在那段约 120 行内联，抽出来两边共用）。
- **代价**：抽函数（无行为变化）+ 新路由约 40 行 + 签名。
- **怎么验**：3 家一次打开 → 打印预览 3 页，每家一页；改 URL 里的 `parties` → 链接失效。

## C 组：统一层与安全头（P1，工程量小、收益是「以后不再各写各的」）

### C1 15 个裸错误页：没有 viewport、没有下一步、没有电话
- **现状**：`c.html('<h3>…')` 共 15 处（`backend/index.js:3787, 3852, 3853, 4858, 4860, 4897, 4901, 5582, 12117, 12119, 17196, 17500, 17546, 17707, 18967`）。没有 `<meta viewport>` → 手机上按 980px 渲染再缩小，字小得看不清；只有一句话，没告诉客户「怎么办」。
- **为什么是问题**：链接过期是**必然会发生**的（7 天 TTL）。客户看到的第一屏就是这种页面。
- **改法**：新增

  ```js
  const errorPage = ({ title, why, how, contact }) => `<!doctype html><html lang="zh-CN"><head><meta charset="utf-8">
  <meta name="viewport" content="width=device-width,initial-scale=1">
  <title>${escHtml(title)}</title><style>${A4_CSS}</style></head><body><div class="sheet">
  <h1>${escHtml(title)}</h1>
  <p style="text-align:center;color:#444">${escHtml(why || '')}</p>
  <p style="text-align:center">${escHtml(how || '回小程序 → 报表 → 点「打印版」，会生成一条新链接')}</p>
  ${contact ? `<p class="tip">有疑问打 ${escHtml(contact)}</p>` : ''}
  </div></body></html>`
  ```
  15 处统一替换，`how` 按页面写具体路径（对账单/工资单/报价/报表各不同），`contact` 取 `getTitle(db).phone`。
- **代价**：1 个 helper + 15 处替换；文案要逐条写。
- **怎么验**：把某条链接的 `x` 改成一个过期时间戳 → 打开后是带样式、有下一步、有电话的页面；手机视图下字号正常。

### C2 四份转义函数，其中一份不转引号
- **现状**：`escHtml`（`:3803`，转 `&<>"`）、局部 `esc`（`:3582`、`:3896`，同）、局部 `esc`（`:3789`，**只转 `&<>`，不转 `"`**）。
- **为什么是问题**：`:3789` 那份现在只用于文本节点，暂时安全；哪天有人把它的结果放进 `title="…"` 或 `onclick="…"`，客户名里带个双引号就能截断属性 —— 这是 XSS 的典型入口，而且是「以前没问题」型的隐性债。
- **改法**：删掉三份局部实现，全用 `escHtml`；`/pc` 里那份（`backend/index.js:8188` 段内，转 `&<>"`）也统一。
- **代价**：删 30 行，替换调用点（grep 可数）。
- **怎么验**：`grep -c "function esc(" backend/index.js` 归零；建一个名字带 `" < > &` 的客户，对账单/客户页显示为原文而非破坏布局。

### C3 安全响应头一个都没有
- **现状**（实测一条签名对账单的响应头）：`cache-control: no-cache, no-transform` ✅、`etag: W/"…"` ✅、`referrer-policy` ✗、`x-robots-tag` ✗、`x-frame-options` ✗、`x-content-type-options` ✗。
- **为什么是问题**：①URL 里带签名 `t`/`x`，页面里若有任何外链（现在是 `tel:`，将来可能加地图/二维码图片），`Referer` 会把签名泄漏给对方站点；②打印页若被搜索引擎或微信爬虫抓到，客户名+金额可能进索引；③缺 `nosniff` 是老问题但一行就能补。
- **改法**：在 `applyEtag`（`:1667`）所在的中间件里，对所有 `text/html` 响应统一设：

  ```js
  h.set('Referrer-Policy', 'no-referrer')
  h.set('X-Robots-Tag', 'noindex, nofollow, noarchive')
  h.set('X-Frame-Options', 'DENY')
  h.set('X-Content-Type-Options', 'nosniff')
  ```
  签名页额外 `h.set('Cache-Control', 'no-store')`（防「后退」直接看到金额；现在 `no-cache` 已经要求回源，但 bfcache 仍可能显示）。
- **代价**：6 行，一处生效。
- **怎么验**：`fetch` 任一打印页打印响应头；`curl -I` 线上版确认 CF 没剥掉（若被剥，改用 `_headers` 或 `transform` 中间件兜底）。

### C4 `/guide` 27.6 KB 每次全量下发、且不标版本
- **现状**：`/guide`（`backend/index.js:8181`）`await import('./guide.js')` 返回 `GUIDE_HTML`，28508 字符；内容里没有「对应哪个版本」，功能改过几轮后容易和实际界面不一致。
- **改法**：①页脚自动印 `对应版本 ${c.env.APP_VERSION} · 生成于 ${c.env.APP_BUILT}`（一行模板变量）；②`Cache-Control` 已有 `no-cache` + ETag（304 便宜），不用动；③可选：把 13 个 `<h2>` 拆成锚点目录（已有目录，检查锚点是否可点）。
- **代价**：1 行 + 检查目录。
- **怎么验**：`/guide` 页脚能看到版本号；改一节内容后 ETag 变化 → 客户端重新取。

## D 组：老板在电脑前（P1，价值最高，要新写页面）

### D1 现状：`/pc` 是「导入导出 + 账套管理」，不是「看账」
- **现状**：`/pc`（`backend/index.js:8188`，约 700 行内联 HTML+JS，38.7 KB）能：输入口令（存 localStorage）、快捷面板、下载模板、上传预览、确认导入、导出 JSON、整本导出/导入、一键初始化、存档、账套管理（4 个 `renBook`）、超级口令、员工账号增删改与权限。**没有任何「看账」能力**：看不到本月利润、谁欠最多、逾期多少、现金还能撑几个月。老板坐在电脑前仍要掏手机。
- **为什么是问题**：不是 bug，是产品缺口。老板的真实动作是「月底在电脑前把账过一遍、把该催的挑出来」——现在得在小程序上一个个翻。

### D2 新增 `/desk` 只读看账台
一屏（桌面两栏，手机一栏）：

| 区域 | 数据来源（复用现有只读接口，不新写 SQL） |
|---|---|
| 顶部 5 个数：本月利润 / 本月收款 / 逾期总额 / 现金能撑几个月 / 最大客户占比 | `/kpi`、`/ar-summary`、`/cash-bridge` |
| 逾期表 Top 20（客户 / 金额 / 逾期天数 / 电话），行点击进 `/track?...` 只读页 | `/due-schedule?type=ar` |
| 本月新单 / 未结单据 | `/dashboard`、`/ar?limit=` |
| 按钮：批量打印本月对账单（进 `/statements-print`，见 B4）、看月报（进 `/report-print`）、导出备份 | 已有路由 |

## 有意不做（说明理由，避免下一轮重复讨论）

1. **不做 SPA/React 重写前端网页**：网页端是「发链接给人看」，价值在稳、快、离线可打印；引入构建链会让「一个 HTML 字符串就能发出去」的优势消失，且与小程序重复维护两套 UI。
2. **不做暗色主题**：只做 `color-scheme: light`，防止深色模式下输入框变色。真做暗色要重画 13 张 A4 打印页（打印必须白底），收益为零。
3. **不做真页码**：Chrome 不支持 `@page` margin box，要真页码只能上 puppeteer 出 PDF（Cloudflare Workers 跑不了），代价远超收益 → 用「页脚固定信息 + 提示用户勾页眉页脚」替代（见 B2）。
4. **不在 `/desk` 做写操作**：写账逻辑只有一套（小程序），网页端只读，避免两套并发写与权限面扩散。以后要写，先做「写接口归属闸 + 幂等键」复用，再动 UI。
5. **不给打印页加登录**：打印页靠签名链接，客户不该有账号。安全性靠 TTL（7 天）+ 签名（含 `book`/`party`/`type`/`exp`）+ `t` 与链接一一对应。
6. **不把 `A4_CSS` 外链成静态文件**：打印页要弱网/离线可打开，内联 1.4 KB 值得（E3）。
